# 二、需求分析

## 2.1 用户角色

| 角色 | 特征 | 核心诉求 |
| --- | --- | --- |
| 产品经理 | 有需求但缺乏技术落地规划 | 快速梳理功能、模块与排期 |
| 创业者 | 有创意但缺乏商业规划 | 梳理定位、商业模式与落地计划 |
| 开发者 | 有技术想法但缺乏整体设计 | 生成技术选型与开发规划 |
| 创意爱好者 | 想法零散、不成体系 | 将奇思妙想整合为雏形方案 |

## 2.2 功能需求

### 2.2.1 用户认证

- 注册：账号（1-20 位）、密码（6-20 位）、确认密码，账号全局唯一；
- 登录：账号 + 密码校验；
- 退出：清除登录态；
- 登录鉴权：未登录用户自动跳转登录页。

### 2.2.2 方案生成

- 输入三类碎片信息：痛点描述、需求描述、奇思妙想；
- 支持两种模式：工具创新（软件开发规划）、创业创新（创业项目规划）；
- 流式输出生成结果。

### 2.2.3 方案迭代

- 基于当前方案上下文，追加补充需求；
- 输出更新后的完整方案。

### 2.2.4 评论交流

- 查看方案下的所有评论（用户昵称、内容、时间）；
- 发布评论。

### 2.2.5 个人方案管理

- 查看本人历史方案（按模式分类）；
- 查看方案详情；
- 删除方案；
- 修改昵称。

### 2.2.6 悬浮创意助手

- 可拖拽卡通悬浮球，支持位置记忆；
- 通用问答，解答产品使用问题；
- 识别路由指令（如「跳转到工具创新」）并自动跳转；
- 未接入 AI 时仍可通过本地 FAQ 回答项目问题并完成页面跳转。

## 2.3 非功能需求

- **性能**：AI 响应采用流式输出，首字节时间短，体验流畅；
- **安全**：密码加密存储、JWT 鉴权、HttpOnly Cookie 防 XSS；
- **可用性**：表单友好校验与错误提示，全局 toast 反馈；
- **可维护性**：代码结构清晰，关键逻辑有注释，遵循主流规范；
- **可部署性**：SQLite 单文件数据库，零额外服务依赖，可一键部署。

## 2.4 数据模型需求

系统需要三张核心数据表：**User（用户）**、**ProjectPlan（项目方案）**、**Comment（评论）**，通过外键关联，形成"用户-方案-评论"的完整数据链路。
