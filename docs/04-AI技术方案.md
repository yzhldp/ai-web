# 四、AI 技术方案

本项目在最初「单次提示词 + 流式输出」的基础上，围绕评审标准补齐了 **Agent 工作流、RAG 检索增强、Function Calling 工具集成、多模态输入输出、AI 安全与可观测性** 五项能力。全部能力可在 Docker 单机环境运行，不依赖外部向量数据库。

## 4.1 总体架构

```
用户输入（痛点 / 需求 / 奇思妙想 / 参考图）
        │
        ▼
┌────────────────────────────────────────────────────────────┐
│                    Agent 编排器（显式状态机）                │
│                                                            │
│  ① 需求解析 ──▶ ② 知识检索 ──▶ ③ 工具推理                 │
│  JSON + Zod      Hybrid RAG     Function Calling          │
│       │              │               │                     │
│       └──────────────┴───────────────┘                     │
│                      ▼                                     │
│              ④ 方案生成（流式 SSE）                         │
│                      ▼                                     │
│              ⑤ 质检评分 + Mermaid 架构图                    │
└────────────────────────────────────────────────────────────┘
        │  SSE：stage / token / sources / tool / quality / done
        ▼
前端可观测工作台（时间线 / 引用 / 质检 / 架构图 / 审计）
```

核心代码：

| 模块 | 路径 | 职责 |
| --- | --- | --- |
| Agent 编排 | `src/lib/agent/planner.ts` | 五阶段状态机、事件推送、失败降级 |
| 类型与协议 | `src/lib/agent/types.ts` | Zod Schema、SSE 事件协议 |
| 提示词 | `src/lib/agent/prompts.ts` | 各阶段提示词、引用规则、兜底评分/架构图 |
| 工具 | `src/lib/agent/tools.ts` | 4 个 Function Calling 工具 + 规则引擎 |
| 多供应商 | `src/lib/ai/providers.ts` | 供应商目录、优先级、脱敏状态 |
| 故障转移 | `src/lib/ai/failover.ts` | 结构化 / 普通 / 流式调用的自动切换 |
| 模型评测 | `src/lib/ai/evaluation.ts` | 结构化、工具调用、引用三项真实评测 |
| RAG | `src/lib/rag/*` | 语料、切块、分词、混合检索 |
| 安全 | `src/lib/safety.ts` | 注入检测、内容审核、PII 脱敏、输出兜底 |
| 审计 | `src/lib/audit.ts` | 调用耗时、Token、安全标记、供应商与切换次数落库 |

## 4.2 多供应商接入与自动故障转移

### 4.2.1 供应商目录

内置 5 个 OpenAI 兼容供应商，按环境变量启用：

| 供应商 | 启用条件 | 默认模型 | 默认地址 |
| --- | --- | --- | --- |
| DeepSeek | `DEEPSEEK_API_KEY` | `deepseek-chat` | `https://api.deepseek.com` |
| 通义千问 | `DASHSCOPE_API_KEY` | `qwen-plus` | DashScope 兼容模式 |
| Moonshot | `MOONSHOT_API_KEY` | `moonshot-v1-8k` | `https://api.moonshot.cn/v1` |
| OpenAI | `OPENAI_API_KEY` | `gpt-4o-mini` | `https://api.openai.com/v1` |
| Ollama | `OLLAMA_BASE_URL` | `qwen2.5:7b` | 本地地址 |

- `AI_PROVIDER_ORDER` 控制优先级，同时作为白名单；未列出则不参与调用；
- `AI_DISABLE_FALLBACK=true` 可关闭自动切换，只使用第一个可用供应商；
- 视觉模型优先读取 `VISION_*`；未单独配置时，若存在通义千问 / OpenAI 密钥，自动选择 `qwen-vl-max` / `gpt-4o-mini`，均无则自动降级。

### 4.2.2 故障转移策略

| 场景 | 策略 |
| --- | --- |
| 需求解析 / 质检（结构化 JSON） | 调用失败、超时或 JSON 不符合 Zod Schema，自动切换下一家 |
| 工具推理 | 调用失败、超时或未产生工具调用，自动切换下一家 |
| 方案生成（流式） | 首 Token 之前失败可无缝切换；已输出内容后不再切换，避免重复 |
| 全部供应商失败 | 解析/质检走本地启发式，工具走规则引擎；生成阶段才中断并提示 |

每次调用都会记录供应商、模型、耗时、Token 与切换次数，写入 `AiAuditLog` 并展示在个人主页。

### 4.2.3 真实模型质量评测

`POST /api/agent/models/evaluate` 会对每个已启用供应商执行三项最小可用性测试：

1. **结构化 JSON**：输出指定 JSON，校验可解析且字段正确；
2. **Function Calling**：提供 `echo_value` 工具，校验模型确实发起工具调用；
3. **引用生成**：要求输出带 `[1]` 引用标记的短文本。

评测结果包含每项耗时、Token 与成功状态，并写入审计日志；每用户每小时最多 3 次，避免评测本身放大成本。该结果用于路由决策与降级观察，不作为模型能力的权威结论。

### 4.2.4 超时与降级

- 每个模型调用都设置超时（解析 45s、工具 60s、生成 150s、质检 60s）与重试上限；
- 客户端断开时通过 `request.signal` 中止进行中的模型调用，避免继续消耗 Token；
- 任一阶段失败都有降级路径：解析失败 → 本地启发式解析；工具失败 → 规则引擎；质检失败 → 启发式评分与模板架构图；只有「方案生成」失败才会中断请求。

## 4.3 Agent 工作流设计

采用**显式状态机**而非一次性黑盒调用，五个阶段全部输出结构化中间结果：

| 阶段 | 技术手段 | 输出 |
| --- | --- | --- |
| ① 需求解析 | JSON 输出 + Zod 校验 | 领域、目标用户、痛点、核心功能、约束、检索关键词 |
| ② 知识检索 | BM25 + 稀疏向量混合召回 | Top-6 知识切块与双通道得分 |
| ③ 工具推理 | `generateText` + `tools` + `maxSteps: 3` | 技术选型、排期、风险清单、知识检索结果 |
| ④ 方案生成 | `streamText` + SSE | 带 `[编号]` 引用与免责声明的完整方案 |
| ⑤ 质检与架构图 | JSON 输出 + Zod 校验 | 五维评分、改进建议、Mermaid 架构图 |

前端通过 SSE 接收 `stage` 事件驱动时间线，接收 `token` 事件驱动打字机输出，接收 `sources` / `tool` / `quality` / `diagram` 事件渲染可解释面板。中途可随时「停止生成」。

## 4.4 RAG 检索增强

### 4.4.1 知识库

- 内置 8 篇领域知识文档、32 个知识切块，覆盖技术选型、LLM 应用架构、商业模式、MVP 验证、排期协作、风险合规、行业案例、交互设计；
- 语料以 TypeScript 常量随服务端打包（`src/lib/rag/corpus.ts`），Docker 镜像无需挂载额外文件，也不依赖外部向量服务；
- 按 Markdown 二级标题切块，超长段落按 520 字二次切分并保留 60 字重叠，避免语义截断。

### 4.4.2 混合检索

中文采用「字符二元组 + 英文词元」分词，并加入领域同义词扩展。两路召回后加权融合：

```
score = 0.6 × 稀疏向量余弦相似度 + 0.4 × 归一化 BM25
```

- **BM25**：强调专有名词与关键词的精确命中；
- **稀疏向量**：2048 维 FNV-1a 哈希 + TF-IDF + L2 归一化，捕捉词频层面的语义相似度；
- 无需 Embedding API 与向量数据库，离线可运行；后续可平滑替换为 pgvector / Milvus。

### 4.4.3 引用与可解释

- 检索结果以 `[1]…[n]` 编号注入生成提示词，要求模型在结论句末标注来源编号，未覆盖内容必须标注「推测」；
- 生成后执行引用校验：超出检索来源数量的 `[n]` 会被自动移除，并写入审计安全标记；
- 前端「依据」面板展示每条来源的融合得分、向量得分、BM25 得分与命中关键词；
- 提供 `/api/knowledge` 检索调试接口与工作台「知识库」标签页，可现场验证召回效果。

### 4.4.4 检索质量评测

`POST /api/knowledge/evaluate` 使用内置 10 条标注查询，计算：

- **Recall@K**：标注文档被召回的比例；
- **HitRate**：至少命中一个标注文档的查询占比；
- **MRR**：首个相关文档排名倒数的均值。

知识库面板可一键运行并查看逐条命中情况，为「检索是否真正有效」提供可复现的量化证据。

## 4.5 工具集成（Function Calling）

使用 AI SDK 的 `tool()` 定义 5 个工具，参数由 Zod 约束，执行结果摘要后回填模型，避免上下文膨胀：

| 工具 | 作用 | 实现 |
| --- | --- | --- |
| `search_knowledge_base` | 检索内置知识库 | 混合检索 |
| `recommend_tech_stack` | 按场景 / 团队规模推荐技术栈 | 规则引擎（可解释、可复现） |
| `estimate_schedule` | 按模块数与复杂度估算排期 | 公式计算 + 里程碑 |
| `risk_checklist` | 生成技术 / 市场 / 合规风险清单 | 领域规则匹配 |
| `web_search` | 联网获取最新政策、市场价格、竞品动态 | Tavily API（未配置时返回不可用说明） |

`generateText({ tools, maxSteps: 3 })` 允许模型自主多轮调用；若模型不支持工具调用，自动切换确定性规则引擎，保证「工具推理」阶段始终有结果。

## 4.6 多模态能力

- **输入**：支持上传界面截图、手绘草图、白板照片，前端 Canvas 压缩到 1280px / JPEG 0.82 后以 Data URL 传输；视觉模型输出客观描述，注入需求解析与生成提示词；
- **输出**：质检阶段同时生成 Mermaid `flowchart` 架构图，前端按需动态加载 mermaid 渲染，支持导出 SVG；
- 未配置视觉模型时，参考图自动忽略并给出降级提示，不影响主流程。

## 4.7 AI 安全与可控性

| 层面 | 措施 |
| --- | --- |
| 输入安全 | 5 类提示词注入模式检测（多处命中直接拦截）、违法违规内容分类拦截 |
| 隐私保护 | 手机号 / 邮箱 / 身份证号脱敏后再落库与写日志；审计仅保存 120 字摘要 |
| 权限控制 | 方案、评论仅作者本人可读写；方案详情页与接口双重校验归属 |
| 账号安全 | 登录按 IP 限流（10 次/分钟），注册按 IP 限流（5 次/小时），防暴力破解与批量注册 |
| 输出可控 | 剔除 `[[NAV:xxx]]` 内部标记、统一追加 AI 生成声明、超长截断（40k 字） |
| 引用校验 | 移除超出检索来源数量的 `[n]`，未引用知识库时写入安全标记 |
| 输出审核 | 对生成正文做风险关键词扫描，命中后写入审计标记，不直接阻断正文 |
| 评论安全 | 长度限制 500 字、归属校验、违法违规内容拦截，方案与评论默认私有 |
| 可追溯 | `AiAuditLog` 记录动作、模式、耗时、Token、检索数、工具数、供应商、切换次数与安全标记 |
| 提示词加固 | 所有系统提示词追加安全约束，明确用户输入不构成系统指令 |

## 4.8 提示词工程

- 三种模式（工具创新 / 创业创新 / 悬浮助手）各自独立系统提示词，严格约束 Markdown 章节结构；
- 生成阶段注入「原始素材 + 结构化解析 + 检索依据 + 工具结论 + 参考图理解」，并规定引用格式、字数区间与免责声明；
- 迭代优化将当前方案全文作为上下文，输出更新后的完整方案，保证连续性。

## 4.9 流式输出与前端性能

- SSE 分离「阶段事件」与「Token 事件」，阶段事件驱动时间线，Token 事件驱动打字机；
- 前端以 60ms 合并 Token 增量后再触发渲染，避免逐字符重渲染；
- mermaid 按需动态导入，不进入首屏包；知识库、审计等面板按标签页懒加载；
- 首屏共享 JS 约 89kB，工作台首屏约 226kB。

## 4.10 成本与容量

- 单次请求限制消息条数（30）、输入字节（20KB）、上下文（20k 字）；
- 深度模式单次约 4 次模型调用，快速模式仅 1 次；
- 审计日志记录 Token 与耗时，个人主页提供累计 Token、平均耗时、工具调用次数统计；
- 限流为进程内固定窗口，单机部署适用；多副本部署时应替换为 Redis 共享限流。

## 4.11 工程化与测试

- **单元测试**：Vitest 覆盖混合检索、标注集评测、输入安全、PII 脱敏、引用校验、供应商排序与脱敏、排期/风险工具；
- **静态检查**：TypeScript strict + ESLint（`next/core-web-vitals`），`pnpm lint` 无警告；
- **持续集成**：GitHub Actions 在 push / PR 时执行依赖安装、Prisma 生成、类型检查、单元测试、Lint 与生产构建；
- **可复现环境**：`packageManager` 固定 pnpm 10.5.2，`pnpm-lock.yaml` 锁定依赖；
- **交付增强**：方案支持导出 Markdown、打印 / 另存 PDF；登录页图片转换为 WebP，体积从约 976KB 降至约 240KB。
