# 四、AI 技术方案

## 4.1 技术选型

本项目 AI 能力采用 **Vercel AI SDK + DeepSeek API**：

- **Vercel AI SDK**：提供统一的 `streamText` 流式接口，屏蔽底层协议差异，支持 `toDataStreamResponse`（配合 `useChat` 客户端）与 `toTextStreamResponse`（纯文本流）两种输出方式；
- **DeepSeek API**：兼容 OpenAI 协议，通过 `@ai-sdk/openai` 的 `createOpenAI` 将 `baseURL` 指向 DeepSeek 服务，性价比高、中文能力强。

## 4.2 模型接入

```ts
import { createOpenAI } from "@ai-sdk/openai";

export function getDeepSeekModel() {
  const provider = createOpenAI({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: process.env.DEEPSEEK_BASE_URL || "https://api.deepseek.com",
  });
  return provider(process.env.DEEPSEEK_MODEL || "deepseek-chat");
}
```

- 默认模型 `deepseek-chat`（通用对话），可切换 `deepseek-reasoner`（深度推理）；
- API Key 仅在服务端读取，不暴露给客户端。

## 4.3 提示词工程

针对不同场景设计独立的系统提示词（System Prompt），统一以中文输出、严格结构化的 Markdown 方案。

### 4.3.1 工具创新模式

输出结构：项目总览 → 痛点清单 → 目标用户 → 核心功能 → 扩展功能 → 模块划分 → 技术选型 → 开发排期 → 风险难点 → 验收标准。

### 4.3.2 创业创新模式

输出结构：项目定位 → 痛点与价值 → 目标人群 → 产品形态 → 差异化 → 竞品简述 → 商业模式 → 落地计划 → 风险对策。

### 4.3.3 悬浮助手

在通用问答基础上，加入**路由指令识别规则**：当用户表达跳转意图时，回复开头输出 `[[NAV:xxx]]` 标记，客户端解析后执行对应路由跳转。

### 4.3.4 统一免责声明

所有方案末尾统一标注：**「本方案仅为创意参考，不代表绝对可行性」**。

## 4.4 流式输出方案

```
客户端 ──POST /api/chat──▶ 服务端 ──streamText──▶ DeepSeek
   ▲                         │
   └──── 逐块接收文本 ◀──── 纯文本流 (toTextStreamResponse)
```

1. 客户端通过 `fetch` 请求 `/api/chat`，传入 `action`（generate/iterate/assistant）、`mode`、`messages` 等参数；
2. 服务端根据 action 与 mode 构建系统提示词，调用 `streamText`；
3. 对于方案生成/迭代，返回 `toTextStreamResponse()`（纯文本流），客户端通过 `ReadableStream` 逐块读取并实时渲染（打字机效果）；
4. 对于悬浮助手，返回 `toDataStreamResponse()`，配合 AI SDK 的 `useChat` Hook 实现聊天流式交互。

## 4.5 方案迭代机制

迭代时，服务端将**当前方案完整内容**作为上下文注入系统提示词，并追加用户补充需求，使模型基于已有方案输出更新后的完整方案，而非从零生成，保证方案的连续性与一致性。
