# 七、创新点说明

## 7.1 技术创新点

### 7.1.1 全栈一体化 + 服务端流式输出

- 采用 Next.js App Router 全栈架构，前端、后端、API 一体化，部署简单；
- 基于 Vercel AI SDK 实现服务端流式输出，生成过程打字机式实时呈现，体验流畅。

### 7.1.2 提示词工程与方案上下文迭代机制

区别于一次性生成，系统支持**基于当前方案上下文的持续迭代**：将已有方案作为上下文注入提示词，用户追加需求即可获得更新后的完整方案，让创意不断进化。同时针对三种使用场景设计了三套结构化系统提示词，约束模型输出稳定的章节结构。

### 7.1.3 轻量安全架构

- SQLite 单文件数据库，零额外服务依赖，开箱即用；
- bcryptjs + jose JWT + HttpOnly Cookie 的安全认证链路，Cookie 按实际协议自动设置 Secure；
- AI 接口按用户维度限流并限制输入规模，防止额度被滥用；
- Prisma 类型安全的 ORM，Schema 即文档，开发高效。

### 7.1.4 路由指令识别

悬浮助手在通用问答之外，通过提示词约束模型输出结构化指令（如 `[[NAV:tool]]`），前端解析后自动执行页面跳转，实现"对话即导航"的交互能力。

### 7.1.5 可观测的多阶段 Agent 工作流

区别于「一次提示词生成全部内容」，系统采用显式五阶段状态机：**需求解析 → 知识检索 → 工具推理 → 方案生成 → 质检与架构图**。每个阶段通过 SSE 推送结构化事件，前端时间线实时展示进度、耗时与中间结论；用户可中途停止，阶段失败时自动降级。生成过程从黑盒变为可解释、可干预的工作流。

### 7.1.6 离线混合检索（BM25 + 稀疏向量）

不依赖外部向量数据库与 Embedding API，内置领域语料按标题切块，中文二元组分词并结合同义词扩展，使用 **0.6 × 稀疏向量余弦 + 0.4 × BM25** 的加权融合完成召回。生成时注入编号来源并要求正文引用，前端展示每条依据的双通道得分，既保证可解释性，也降低了部署与调用成本。

### 7.1.7 Function Calling 工具编排

通过 AI SDK 定义知识检索、技术选型、排期估算、风险清单 4 个工具，参数由 Zod 约束，模型可自主多轮调用；工具不可用时切换确定性规则引擎。工具结果摘要后回填，避免上下文膨胀，同时保证排期与技术选型有可复现的计算依据。

### 7.1.8 多模态输入与可视化输出

支持上传界面截图、手绘草图、白板照片，经视觉模型理解后注入需求；生成完成后自动产出 Mermaid 架构图并支持导出 SVG。未配置视觉模型时自动降级，保证主流程可用。

### 7.1.9 AI 安全与全链路审计

输入侧做提示词注入检测与违法违规拦截，隐私字段脱敏后落库；输出侧清理内部标记、补齐 AI 声明、超长截断；按用户维度做分钟 / 日级限流；每次调用写入审计日志（耗时、Token、检索数、工具数、安全标记），个人主页可查看，实现成本可核算、问题可追溯。

## 7.2 应用创新点

### 7.2.1 碎片化输入 → 结构化输出

打破传统"从 0 到 1"的规划门槛，用户无需具备专业的产品、技术或商业知识，只需输入零散的**痛点、需求、奇思妙想**，AI 自动整合收拢、补全逻辑，输出结构完整、可落地的项目雏形规划。

### 7.2.2 双模式并行生成

同一套交互框架下，针对不同目标场景设计了两套差异化的结构化输出：

- **工具创新**：面向软件开发，输出技术选型、模块划分、开发排期、验收标准等工程化内容；
- **创业创新**：面向商业孵化，输出项目定位、商业模式、竞品分析、落地计划等商业内容。

### 7.2.3 对话即导航的悬浮助手

在首页右下角提供悬浮创意助手，用户用自然语言表达"跳转到工具创新""打开个人主页"等意图，即可完成导航，降低新用户的功能发现成本。

### 7.2.4 视觉与交互设计

登录页采用 Framer Motion 打造的**漫画小人聚合动画**，将"碎片 → 雏形"的产品理念可视化；首页渐变背景 + 入场动效 + 悬浮交互，营造"眼前一亮"的视觉体验。

### 7.2.5 生成过程可视化

工作台将 Agent 的五个阶段、检索依据、工具调用轨迹、质检评分与架构图全部外化为可切换的标签页。用户不仅得到一份方案，还能理解「AI 为什么这样规划」，并可针对薄弱维度继续迭代。

### 7.2.6 双模式差异化输出

工具创新模式输出技术选型、模块划分、开发排期与验收标准；创业创新模式输出项目定位、商业模式、竞品与落地计划。两种模式分别配置知识检索与工具策略，避免"一套模板套所有场景"。
