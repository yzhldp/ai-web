# 免费部署上线一个月方案

本文档提供将「创意雏形合成助手」免费部署上线（约一个月、覆盖比赛周期）的多种方案，按推荐程度排序。

> 本项目使用 **SQLite 单文件数据库**，因此部署的关键点是选择**提供持久化磁盘**的平台，避免重启后数据丢失。

---

## 方案一：Vercel + 免费云数据库（最省心，推荐）

Vercel 对 Next.js 支持最好，免费额度充足；但 Vercel 文件系统是只读/易失的，不能直接使用 SQLite，需要把数据库切换到免费的 Serverless Postgres。

### 步骤

1. 注册 [Vercel](https://vercel.com)，导入 GitHub 仓库；
2. 在 Vercel 项目设置中配置环境变量：
   - `DEEPSEEK_API_KEY`
   - `JWT_SECRET`（随机强密钥）
   - `DATABASE_URL`（指向下面的免费 Postgres）
3. 申请免费 Postgres：
   - [Neon](https://neon.tech)（免费档）或 Vercel 内置 Postgres；
   - 复制其连接串为 `DATABASE_URL`；
4. 修改 `prisma/schema.prisma` 的 provider 为 `postgresql`：
   ```prisma
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```
5. 本地执行迁移并推送，或将 `prisma migrate deploy` 加入构建命令；
6. 部署后访问 Vercel 提供的域名。

**优点**：最省心、自动 CDN、免费额度足够；**缺点**：需将 SQLite 换为 Postgres。

---

## 方案二：Koyeb 免费实例 + 持久化卷（保留 SQLite，推荐）

[Koyeb](https://www.koyeb.com) 免费档提供 **1 个 Web 服务 + 持久化 Volume**，可直接运行带 SQLite 的容器，**代码零改动**。

### 步骤

1. 注册 Koyeb，创建 App，选择 **Docker** 方式（使用仓库内 `Dockerfile`）；
2. 创建 Volume（如 1GB），挂载到容器内 `/app/prisma/data`；
3. 配置环境变量：
   - `DATABASE_URL="file:./data/dev.db"`（指向持久化卷目录）
   - `DEEPSEEK_API_KEY`
   - `JWT_SECRET`
   - `DEEPSEEK_MODEL`
4. 启动服务，Koyeb 自动构建镜像并运行；
5. 访问分配的 `*.koyeb.app` 域名。

**优点**：保留 SQLite、代码零改动、有持久化磁盘；**缺点**：免费实例性能一般，可能休眠。

## 方案三：Render 免费 Web Service + 免费 PostgreSQL

[Render](https://render.com) 免费档提供 Web Service（休眠制）与免费 PostgreSQL（约 30 天有效期）。

1. 新建 Web Service，连接 GitHub 仓库；
2. 构建命令 `pnpm build`，启动命令 `pnpm start`；
3. 新建免费 PostgreSQL，获取连接串设为 `DATABASE_URL`；
4. 将 `prisma/schema.prisma` provider 改为 `postgresql`；
5. 部署。

**优点**：操作简单、有数据库；**缺点**：免费实例空闲 15 分钟会休眠（冷启动慢），免费 Postgres 约 30 天后需升级。

## 方案四：Railway / Zeabur（容器化一键部署）

- **Railway**：提供一次性试用金（约 $5），支持 Docker + Volume，保留 SQLite 即可，适合一个月短期演示；
- **Zeabur**：国内可访问、有免费额度，支持 Docker 部署 + 持久化卷。

均使用仓库内 `Dockerfile`，配置环境变量后即可部署。

---

## 方案五：本地运行 + 内网穿透（零成本、临时演示）

若仅需评审时短时演示，可在本地运行后使用免费内网穿透工具暴露公网地址。

```bash
# 1. 本地启动
pnpm install && cp .env.example .env && pnpm db:push && pnpm build && pnpm start

# 2. 内网穿透（任选其一）
# cpolar / ngrok / cloudflared
cloudflared tunnel --url http://localhost:3000
```

**优点**：完全免费、改动为零；**缺点**：依赖本地机器在线，地址不稳定。

## 通用部署清单

| 项目 | 内容 |
| --- | --- |
| 环境变量 | `DEEPSEEK_API_KEY`、`JWT_SECRET`、`DATABASE_URL`、`DEEPSEEK_MODEL` |
| 构建命令 | `pnpm build`（含 `prisma generate`） |
| 启动命令 | `pnpm start` |
| 数据库初始化 | `pnpm db:push`（SQLite）或 `prisma migrate deploy`（Postgres） |
| 端口 | 3000 |
| 持久化 | SQLite 需挂载持久卷，或改用云 Postgres |

## 推荐结论

- **追求省心 + 稳定**：选择**方案一（Vercel + Neon Postgres）**；
- **想保留 SQLite、零改动**：选择**方案二（Koyeb 免费实例 + Volume）**；
- **仅比赛当天演示**：选择**方案五（本地 + 内网穿透）**。

> 无论哪种方案，请务必：① 将 `JWT_SECRET` 换成随机强密钥；② 不要提交真实 `.env`；③ 确认 `DEEPSEEK_API_KEY` 已充值余额。
