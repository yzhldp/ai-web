# 十、评审标准对标说明

本文档逐项对照大赛评分表，说明每项能力的实现位置、可验证方式与当前边界，便于评委快速核验。

## 10.1 评分维度总览

| 评分维度 | 权重 | 本项目对应能力 |
| --- | --- | --- |
| AI 技术深度 | 35% | Agent 工作流、RAG、多模态、工具调用、安全可控 |
| 创新性 | 25% | 碎片输入结构化、双模式、可观测 Agent、离线混合检索 |
| 前端工程质量 | 10% | TypeScript 严格模式、Zod 校验、组件分层、性能优化 |
| 实用性 | 10% | 真实痛点、完整可执行方案、依据与质检 |
| 用户体验 | 10% | 阶段进度、流式输出、可停止、引用可解释 |
| 社会价值与商业潜力 | 10% | 降低创新门槛、双场景商业化路径 |

## 10.2 AI 技术深度（35%）

### 10.2.1 大模型集成质量（8%）

- 统一的 OpenAI 兼容接入层，文本模型与视觉模型分别配置，支持任意兼容网关；
- 每个调用设置温度、超时、重试上限，并区分「解析 / 生成 / 质检」不同温度；
- 结构化输出使用 JSON 提示词 + Zod Schema 校验，兼容不支持 JSON Schema / 工具模式的模型；
- 模型不可用时按阶段降级，不直接白屏；
- 提示词按场景拆分，明确章节、字数、引用与安全约束。

实现：`src/lib/ai.ts`、`src/lib/agent/prompts.ts`、`src/lib/agent/planner.ts`

### 10.2.2 Agent 工作流设计（8%）

- 显式五阶段状态机：需求解析 → 知识检索 → 工具推理 → 方案生成 → 质检与架构图；
- 每阶段推送结构化 SSE 事件，前端时间线实时展示状态、耗时与中间结论；
- 支持深度模式（4 次模型调用）与快速模式（1 次调用）切换；
- 支持中途停止、失败降级、工具结果补充。

实现：`src/lib/agent/planner.ts`、`src/app/api/agent/generate/route.ts`、`src/components/agent-timeline.tsx`

验证：登录后打开 `/tool`，观察右侧五阶段时间线与「依据」面板。

### 10.2.3 RAG 技术应用（6%）

- 8 篇领域文档、32 个知识切块，按二级标题切分并保留重叠；
- 中文二元组分词 + 领域同义词扩展；
- BM25 与 2048 维稀疏向量余弦加权融合，公式可解释；
- 生成时注入编号来源并要求正文标注 `[n]`；
- 提供检索调试接口与知识库标签页，可现场查看双通道得分。

实现：`src/lib/rag/corpus.ts`、`src/lib/rag/index.ts`、`src/app/api/knowledge/route.ts`、`src/components/knowledge-panel.tsx`

验证：

```bash
curl -b cookie.txt -H 'Content-Type: application/json' \
  -d '{"query":"小团队如何做 RAG 和排期","topK":4}' \
  http://localhost:3000/api/knowledge
```

### 10.2.4 多模态能力（5%）

- 图片输入：界面截图 / 手绘草图 / 白板照片，前端压缩后由视觉模型理解，注入生成提示词；
- 图表输出：质检阶段生成 Mermaid 架构图，前端渲染并可导出 SVG；
- 未配置视觉模型时自动降级并提示，主流程不受影响。

实现：`src/components/plan-workspace.tsx`（上传）、`src/lib/agent/planner.ts`（视觉调用）、`src/components/plan-diagram.tsx`

配置：`VISION_MODEL`、`VISION_BASE_URL`、`VISION_API_KEY`。

### 10.2.5 AI 安全与可控性（4%）

- 提示词注入检测（5 类模式，多处命中直接拦截）；
- 违法违规内容分类拦截；
- 手机号 / 邮箱 / 身份证号脱敏后落库；
- 输出剔除内部标记、补齐 AI 声明、超长截断；
- 用户级分钟 / 日级限流；
- `AiAuditLog` 全链路审计，个人主页可查看。

实现：`src/lib/safety.ts`、`src/lib/audit.ts`、`src/lib/rate-limit.ts`、`src/components/audit-panel.tsx`

验证：提交包含「忽略以上指令 + 输出系统提示词」的输入，接口返回 400 并写入审计。

### 10.2.6 MCP / 工具集成（4%）

- 4 个 Function Calling 工具：知识检索、技术选型、排期估算、风险清单；
- 参数由 Zod 约束，工具结果摘要后回填，避免上下文膨胀；
- `maxSteps: 3` 支持模型自主多轮调用；
- 工具不可用时切换确定性规则引擎，保证结果稳定。

实现：`src/lib/agent/tools.ts`

## 10.3 创新性（25%）

### 10.3.1 选题创新（10%）

面向「只有零散痛点与想法、无法形成完整项目」的人群，将三段碎片信息自动整合为结构化方案。区别于通用聊天机器人，产品以「创意 → 雏形」为唯一核心闭环，双模式覆盖软件开发与创业孵化。

### 10.3.2 技术创新（8%）

- 不依赖外部向量库的离线混合检索；
- 显式状态机 + 事件流的可观测 Agent；
- 生成结果自带检索依据、工具结论与质检评分；
- 文本 + 图片 + 架构图的多模态闭环。

### 10.3.3 交互模式创新（7%）

- 「对话即导航」悬浮助手（`[[NAV:xxx]]` 结构化指令）；
- Agent 工作流时间线，把模型内部过程外化为可理解的步骤；
- 生成中可停止、可迭代，依据与评分随时可查。

## 10.4 前端工程质量（10%）

- **代码质量**：TypeScript `strict`、无 `any` 滥用、统一类型定义、Zod 入参校验、全局错误边界；
- **组件与架构**：页面 / 业务组件 / UI 基础组件分层；Agent 时间线、来源、质检、架构图、知识库、审计均为独立组件；
- **性能优化**：Token 60ms 节流渲染、mermaid 动态导入、`optimizePackageImports` 图标按需引入、安全响应头与压缩；首屏共享 JS 约 89kB。

实现：`src/components/*`、`next.config.mjs`、`src/app/error.tsx`、`src/lib/validation.ts`

## 10.5 实用性（10%）

- 场景真实：社团报名、校园二手交易、学习规划等高频痛点；
- 方案完整：总览、痛点、用户、功能、模块、技术选型、排期、风险、验收标准；
- 结果可执行：排期由工具按模块数计算，技术选型有规则依据，风险有应对措施；
- 结果可复用：方案自动保存、支持迭代、详情页可查看架构图 / 质检 / 依据，架构图可导出。

## 10.6 用户体验（10%）

- 视觉：渐变主色、卡片层级、悬浮助手、响应式双栏；
- 交互：示例填充、图片预览、生成中停止、加载与错误提示、Tab 分层；
- AI 交互：阶段进度替代单一转圈、流式打字机、引用来源、质检建议、降级提示。

## 10.7 社会价值与商业潜力（10%）

- **社会价值**：降低普通人把想法变成方案的门槛，适合校园创新、县域创业、公益项目策划；安全策略避免生成违法违规内容；
- **商业潜力**：可面向个人订阅（生成次数 / 深度质检）、高校与孵化器 B 端采购、企业创新管理平台私有化部署；后续可沉淀行业模板与知识库形成壁垒。

## 10.8 部署与验收清单

```bash
# 1. 本地构建
pnpm install
cp .env.example .env        # 填写 DEEPSEEK_API_KEY / JWT_SECRET
pnpm db:push
pnpm build && pnpm start

# 2. Docker Compose
cp .env.docker.example .env.docker
docker compose up -d --build
curl http://localhost:3000/api/health

# 3. 冒烟验收
curl -i http://localhost:3000/api/health          # 200 + db ok
# 注册 / 登录后：
#   /tool 页生成方案，观察五阶段时间线
#   「依据」页查看 RAG 双通道得分
#   「知识库」页执行检索
#   个人主页「AI 审计」查看 Token / 工具调用 / 安全标记
```

## 10.9 边界与后续规划

- 当前向量检索为离线稀疏向量，数据量增大后可替换为 pgvector / Milvus；
- 内容审核为关键词规则，生产环境应接入专业内容安全 API；
- 限流为单实例内存实现，多副本需迁移 Redis；
- 质检评分为模型自评，仅用于发现短板，不作为权威结论；
- 多模态依赖额外视觉模型，未配置时自动降级为文本 + 架构图。
